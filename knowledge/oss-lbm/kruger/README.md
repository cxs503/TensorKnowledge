## What is in the package

**16 claims**, all `draft` (`assessment_status: unassessed`, no review events, no
self-approval).  Epistemic split — deliberately conservative:

| status | count | meaning here |
|---|---|---|
| `established` | 12 | pure code facts: the claim states *what the shipped code does*, and the evidence is a verbatim, line-pinned quotation from that code |
| `well-supported` | 3 | code fact **plus** an executed verification run that reproduces the documented behaviour |
| `provisional` | 1 | code fact verified, but the claimed benefit (effect of the force-consistent initialisation on transient error) was not tested |
| `contested` | 1 | the repository's documented "exact solution" statement was only reproduced for part of the tested resolutions — recorded as a negative result, not smoothed over |

The 16 claims cover: Poiseuille with half-way bounce-back (magic relaxation time, linear
equilibrium, PBBC inlet/outlet), Couette with a moving bounce-back wall, the wet-node wall
family and wet-node Poiseuille geometry, the two-axis body-force discretisation matrix and
the force/pressure driving split, the force-consistent initialisation, the Taylor-Green
analytic solution and its seven-implementation backend ladder, Shan-Chen pseudopotential +
Laplace-pressure surface-tension measurement, immersed-boundary LBM Poiseuille, the TRT
magic parameter (Λ = 1/6 vs 1/12 pair), the cylinder cross-flow setup (Λ = 1/4), and the
scope limit of the documented exactness.

## GAP anchor

Every claim is anchored to **`GAP-LBM-BENCH-METHODOLOGY`** (registered in
`GAP-ANCHORS.md`, owner = this ingestion line).  The gap: TensorLBM lacks a written,
executable methodology that turns the published benchmark case spectrum
(Poiseuille / Couette / Taylor-Green / Young-Laplace droplet / cylinder cross-flow) into
acceptance criteria — which reference quantity, which boundary-condition dialect, which
tolerable deviation at which resolution.

## Provenance deviation (honest note)

The mission brief assumed the repository was cached at `/root/oss-cache/`.  That directory
**does not exist** in this image and no cached directory matches the repo slug, so the
source could not be read from the cache (`insufficient` for the cache check).  Instead the
checkout was fetched from the upstream remote at the commit recorded above, and every
quotation is pinned twice: by `file:line` span and by the file `sha256` in
`artifacts/oss-lbm-kruger/kruger_source_index.json`.  The quotes are therefore auditable
against upstream even though the cache was missing.  `GAP-ANCHORS.md`, this README, the run
logs and the analysis scripts are the only produced artifacts; nothing upstream was
modified.
