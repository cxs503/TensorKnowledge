## 1. 目的（案例介绍）

## 2. 方法

本任务的「方法」由四部分组成：对标分析框架、数据来源与采集、判读流程（含覆盖度 rubric）、证据分级规则。全部可在工作树内复算：`python3 artifacts/ai-native-infra-v1/build_evidence.py` → `python3 artifacts/ai-native-infra-v1/make_report.py`。

### 2.1 对标分析框架：十方向 × 六准则

**维度选取**：对基础设施做切面分解（身份/运行时/能力面/记忆/数据/协作/资源/安全/验证/自我改善）——该十维划分的目的是让「传统 IT 基线」与「AI 原生所需」在同一张表上逐格可比，避免以功能清单代替范式比较。

**覆盖度 rubric（六准则，每准则 0–3 分，满分 18）**——分数不是印象分，每格必须能指向证据：

| 准则 | 含义 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|
| C1 原语 | 机制是否作为基建组件存在 | 无 | 仅文档/设计 | 部分落地 | 组件化并被复用 |
| C2 机器强制 | 是纪律还是可执行门 | 无 | 约定 | 部分门 | 可红队验证的门 |
| C3 可审计 | 动作留痕可回放 | 无 | 手工记录 | 部分留痕 | 事件流/DB 全留痕 |
| C4 独立验证 | 执行成功 ≠ 通过 | 无 | 自检 | 部分独立 | 独立复算/盲评 |
| C5 规模实证 | 有 n≥10 的真实样本 | 无 | n<10 | 单场景 | 多场景 + 可量化 |
| C6 缺口闭合 | 首要缺口是否落地/在派 | 无动 | 已识别 | 已派单 | 已验收闭环 |

**分带阈值**：总分 ≥16 = 强轴；12–15 = 中轴；<12 = 弱轴。阈值与打分写在 `build_evidence.py::DIRECTIONS`，评审可改参数重跑，分数随之变化（可证伪）。**该 rubric 是自评，不是基准测试结论**。

⚠ v1→v2 分带变化（rubric 化后的直接后果，如实说明）：D1 身份与授权由 v1 的「弱轴」升为**中轴**（因席位↔模型解耦有了 API 级实测 C1），D4 记忆由「中轴」降为**弱轴**（任务态连续性缺口仍封顶 C6=1）。这说明 v1 的分档是叙事性的，v2 是可复算的。

### 2.3 判读流程（四条硬规则）

1. **先判可复算性，再下结论**：任何数字先问「能否从工件重算」，不能则不得以数字形式出现。
2. **反证优先**：与 v1 结论冲突时以复算为准（示例：v1 写「autoheal 17 s 自愈」，源码 CYCLE=60 s 直接推翻，见 §4.2 C4）。
3. **缺口与覆盖对称披露**：每个方向必须同时给出「已覆盖什么」和「缺什么」，防止自评通胀。
4. **证据分级落地**（下表），QUALITATIVE 断言在正文中以「定性观察」标注，且不得进入关键结果数字表。

| 等级 | 定义 | 本报告条数 |

| QUANT_LOG | 可从宿主日志复算 | **3** |

### 3.4 三优先落地路径

- **优先一 持续 Harness**（对应 D2 缺口=断点续跑）→ **m1231**：journal + reclaim = resume + 可红验收门（含 m1121 对照）。

- **优先三 协作与知识传承**（D4/D6）：已有三线在跑（目录 + 席位记忆 + EVO-1 三臂），不重复派单，收割后按数据定下一步。

### 3.5 范式判断（结论段）

右侧不推翻左侧：复用成熟技术（PG / k8s / OAuth 思路），在其上加智能体原语抽象（能力卡 / 工作日志 / 演化边界 / 四轴评分）。**真正的范式变化点只有一个**：传统基础设施默认「人负责理解、组织、判断、协调」；AI 原生把这三者逐步移交给智能体，同时必须把系统边界（验证链、预算、白名单）**冻结**为不可演化区——平台已把这四点作为 EVO-1 演化边界固化。

## 5. 局限（honest 披露）

1. **单系统样本（n=1）**：所有运营量来自本平台一套部署（995 单 / 42 席），覆盖度分带不可外推为「一般 AI 原生基建」基准；跨系统对照需第二独立部署。
2. **覆盖度是自评 rubric**：六准则 0–3 分由本报告给出，判据公开可改参数重跑（可证伪但不代表客观真值）；因此 §4.3 的 0% 偏差只覆盖「数字一致性」，不覆盖「打分正确性」。
3. **外部标准核验为摘要级**：NIST/IETF 仅做存在性与方向核验，未逐字读草案全文；个体草案不代表 IETF 共识（C9）。
4. **部分关键断言仍无机器来源**（C8/C10）：委托链深度、撤销级联、role 枚举僵化、质量门判决量等来自事故复盘与制度存在性，缺 DB 级查询接口 → 已降级为定性观察，不得进入关键结果数字表。补接口后可升级。
5. **模型维度口径限制**：missions.model 在早期单上为 NULL（占多数），C1 只统计非空模型，因此「跨换模席位 13/49」是**下界**而非全量；真实换模面可能更大。
6. **图件非物理场量**：本任务无云图/解析解曲线，图 1/图 4 为策略分析图，图 2/图 3 为运营数据图；不可当作 CFD/结构类验证图使用。
7. **未做**：未统计 report_qa 判决量与复现官 strike 率（可作为下一轮 D9 量化的第一步）；未对 m1231/m1232 在建件做验收。
