## 1. 双轴分类体系

知识件挂双轴——方法轴 × 领域轴，每个知识件必须同时标注两轴坐标。

### 1.1 方法轴（Method Axis）

九棵能力树，每棵对应一种数值方法/工具：

| 轴值 | 方法 | 能力树根节点 |
|------|------|-------------|
| `lbm` | Lattice Boltzmann Method | 碰撞模型 → 边界格式 → 稳定性分析 → 代码生成 → 并行扩展 |
| `fem` | Finite Element Method | 单元族 → 形函数 → 积分方案 → 求解器 → 后处理 |
| `fvm` | Finite Volume Method | 通量重构 → 限制器 → 时间推进 → 网格适配 → 并行 |
| `sph` | Smoothed Particle Hydrodynamics | 核函数 → 粒子搜索 → 边界处理 → 张力模型 → 耦合 |
| `dg` | Discontinuous Galerkin | 基函数 → 数值通量 → 斜率限制 → 自适应 → 隐式求解 |
| `dem` | Discrete Element Method | 接触模型 → 时间步 → 颗粒生成 → 边界 → 耦合 |
| `bem` | Boundary Element Method | 格林函数 → 离散化 → 奇异积分 → 快速多极子 → 耦合 |
| `cad` | Computer-Aided Design | 几何表示 → 参数化 → 网格生成 → 变形 → 优化 |
| `coupled` | Multi-Physics Coupling | 分区/单体 → 界面条件 → 时间同步 → 收敛加速 → 守恒 |

### 1.2 领域轴（Domain Axis）

船舶与海洋工程 + 基础物理，共 12 个领域：

| 轴值 | 领域 | 典型物理量 |
|------|------|-----------|
| `resistance` | 阻力 | 阻力系数 Cd、摩擦阻力、兴波阻力、压差阻力 |
| `propulsion` | 推进 | 推力系数、扭矩、敞水效率、空化数 |
| `seakeeping` | 耐波 | RAO、运动幅值、波浪载荷、砰击 |
| `maneuvering` | 操纵 | 回转直径、航向稳定性、操纵导数 |
| `ice` | 冰区航行 | 冰载荷、破冰阻力、Lindqvist 公式、IACS 冰级 |
| `multiphase` | 多相流 | 体积分数、界面张力、相变、空化 |
| `structural-hydro` | 结构水动力 | 湿模态、水弹性、砰击压力、疲劳 |
| `full-scale-experiment` | 实船实验 | 实船阻力、自航因子、尺度效应、ITTC 程序 |
| `turbulence` | 湍流 | 雷诺应力、能谱、壁面律、LES/DNS |
| `two-phase` | 两相流 | 自由面、VOF/Level-Set、破碎/合并 |
| `interface` | 界面 | 接触线、润湿角、Marangoni 效应 |
| `general-physics` | 基础物理 | 守恒律、量纲分析、相似律、解析解 |

### 1.3 双轴坐标示例

```
tkdc:lbm:collision-space-selection
  method_axis: lbm
  domain_axis: general-physics

tkac:lbm:poiseuille-lbm
  method_axis: lbm
  domain_axis: general-physics

tkrc:fvm:tvd-shock-tube
  method_axis: fvm
  domain_axis: turbulence
```

## 2. 六形态 Schema（Agent-Ready）

六形态知识件，建于四契约信任层（KO/KE/PR/RE）之上，面向智能体自动消费。

| 形态 | Schema | 用途 | 智能体消费模式 |
|------|--------|------|---------------|
| **DecisionCard** | `decision-card.schema.json` | 情境→选项→取舍→选择判据 | 检索匹配 context → 评估 criteria → 自动选型 |
| **RecipeCard** | `recipe-card.schema.json` | 目标→步骤→验证→参考实现→常见错 | 按步骤执行 → 每步自动验证 → 遇错查 PitfallCard |
| **PitfallCard** | `pitfall-card.schema.json` | 错误签名→根因排序→修法→判伪史 | 异常匹配 error_signature → 按 likelihood 排序排查 → 执行 fix |
| **AnchorCard** | `anchor-card.schema.json` | 基准→期望值+容差→跑法→验收线 | 自动运行基准 → 比对 expected_values → 判定 pass/fail |
| **MethodCard** | `method-card.schema.json` | 本质/参数空间/成本/成熟度/替代 | 方法选型时评估 parameter_space + cost_profile + maturity |
| **GapCard** | `gap-card.schema.json` | 缺什么/为何难/已试什么 | 识别能力缺口 → 规划填补路径 → 关联 attempts |

### 2.1 公共字段

所有六形态共享以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识，格式 `tk{dc\|rc\|pc\|ac\|mc\|gc}:<method>:<slug>` |
| `kind` | const | 形态标识（`decision-card` / `recipe-card` / ...） |
| `title` | string | 人类可读标题 |
| `method_axis` | enum | 方法轴坐标 |
| `domain_axis` | enum | 领域轴坐标 |
| `version` | string | semver 版本号 |
| `status` | enum | `draft` / `reviewed` / `published` / `deprecated` |
| `tags` | string[] | 自由标签 |
| `relations` | array | 关系边（见 §3） |
| `provenance` | object | 溯源信息（created_by, created_at, source_refs） |

### 2.2 preconditions 字段规范

每个形态的 `preconditions` 字段统一结构：

```json
"preconditions": {
  "machine_checkable": {
    "Re": {"min": 100, "max": 1e6},
    "dimension": {"enum": ["2D", "3D"]},
    "has_free_surface": false
  },
  "natural_language": [
    "适用于不可压缩流动",
    "假设流体为牛顿流体"
  ]
}
```

- `machine_checkable`: 键值对，智能体可编程验证（数值范围、枚举、布尔）
- `natural_language`: 字符串数组，需人类判断或暂无法程序化的条件

## 3. 关系词表

八种关系词，语义与约束逐词定义：

| 关系词 | 方向 | 语义 | 约束 | 示例 |
|--------|------|------|------|------|
| `supports` | A → B | A 为 B 提供证据/支撑 | 无 | DecisionCard supports MethodCard |
| `refutes` | A → B | A 否定/反驳 B | 无 | PitfallCard refutes RecipeCard |
| `alternative_of` | A → B | A 是 B 的替代方案 | 对称 | MethodCard alternative_of MethodCard |
| `precondition_of` | A → B | A 是 B 的前提条件 | 无 | AnchorCard precondition_of RecipeCard |
| `fixes` | A → B | A 修复 B 中的问题 | **只从 PitfallCard 指出** | PitfallCard fixes RecipeCard |
| `verifies` | A → B | A 验证 B 的正确性 | 无 | AnchorCard verifies RecipeCard |
| `specializes` | A → B | A 是 B 的特化 | 传递 | MethodCard specializes MethodCard |
| `subsumes` | A → B | A 包含/概括 B | `specializes` 的逆 | MethodCard subsumes MethodCard |

### 3.1 关系约束矩阵

| 源形态 \ 目标形态 | DC | RC | PC | AC | MC | GC |
|---|---|---|---|---|---|---|
| DecisionCard | alternative_of | supports | — | — | supports | — |
| RecipeCard | — | — | fixes | verifies | — | — |
| PitfallCard | — | fixes | — | — | — | — |
| AnchorCard | — | verifies | — | — | — | precondition_of |
| MethodCard | supports | — | — | — | alternative_of/specializes/subsumes | — |
| GapCard | — | — | — | — | — | — |

## 4. 与现有机制的对齐说明

### 4.1 四契约承载方式

现有四契约（Knowledge Object / Knowledge Engine / Provenance Record / Review Event）是信任层基础设施。六形态是内容层，挂载方式：

| 契约 | 承载六形态的方式 |
|------|-----------------|
| **KO (Knowledge Object)** | 新增 `kind: "schema"` 类型 + `payload` 字段，payload 为六形态 JSON 实例。KO 的 `object_type` 扩展枚举值：`decision-card`, `recipe-card`, `pitfall-card`, `anchor-card`, `method-card`, `gap-card` |
| **KE (Knowledge Engine)** | 六查询（§4.2）直接遍历六形态的关系图；`by-domain` 按 method_axis + domain_axis 过滤；`by-anchor` 展开 relations 边 |
| **PR (Provenance Record)** | 六形态的 `provenance` 字段直接映射 PR 的 `generated_entity` / `activity` / `attributed_to` |
| **RE (Review Event)** | 六形态的 `status` 变迁由 RE 记录（draft → reviewed → published） |

### 4.2 KE 六查询与关系遍历的映射

| KE 查询 | 六形态映射 | 说明 |
|---------|-----------|------|
| Q1 `claims_by_status` | 按 `status` 过滤六形态 | `status` ∈ {draft, reviewed, published, deprecated} |
| Q2 `evidence_by_relation` | 按 `relations[].relation_type` 过滤 | 遍历八种关系词 |
| Q3 `provenance_chain` | 六形态 `provenance` → PR 链 | 溯源到 source_refs |
| Q4 `claims_by_domain` | 按 `method_axis` + `domain_axis` 过滤 | 双轴联合查询 |
| Q5 `evidence_for_claim` | 按 `relations` 反向查找 | 给定目标 ID，找所有指向它的关系 |
| Q6 `stats` | 六形态计数 + 关系分布 | 按 kind / method_axis / domain_axis / status 聚合 |

### 4.3 盘点产出到六形态的重铸规则表

| 现有产出 | 重铸为 | 规则 |
|----------|--------|------|
| OSS 方案扫描结果（oss-lbm claims） | MethodCard + DecisionCard | claim → MethodCard（描述方法本质）；claim.notes → DecisionCard.options |
| GAP 锚（GAP-LBM-MCMP-POISEUILLE） | AnchorCard | 基准名 → benchmark.name；期望值 → expected_values；跑法 → run_procedure |
| registry JSON（KE 映射记录） | 全部六形态的 provenance | raw_sha256 → provenance.source_refs；leaf_paths → relations |
| 验证结果（VALIDATION_RESULTS.md） | PitfallCard + AnchorCard | 失败案例 → PitfallCard.error_signature；通过案例 → AnchorCard.acceptance_criteria |
| 教程/配方（tutorial-standard/） | RecipeCard | 步骤 → steps；验证判据 → steps[].verification |

## 5. 面向人类 vs 面向智能体：逐维对照

| 维度 | 面向人类 | 面向智能体 | 设计动因 | 机制落点 |
|------|---------|-----------|---------|---------|
| **单元** | 章节/段落/图表 | 结构化 JSON 对象（六形态） | 智能体需要机器可解析的原子单元 | `kind` 字段 + JSON Schema 校验 |
| **组织** | 线性叙事/层级目录 | 双轴坐标 + 关系图 | 智能体按方法/领域交叉检索，非顺序阅读 | `method_axis` + `domain_axis` + `relations` |
| **形态** | 散文/公式/表格混合 | 六种固定形态，每种有固定字段 | 智能体按形态决定消费策略（决策/执行/排错/验证） | 六个独立 schema |
| **检索** | 关键词/全文搜索 | 结构化过滤（轴值/状态/关系）+ 语义嵌入 | 智能体需要精确过滤而非模糊匹配 | KE Q1-Q6 查询接口 |
| **信任** | 作者声誉/引用次数 | 四契约状态机（evidence_status + review_status + publication_status） | 智能体需要可编程的信任态 | KO 的三态字段 + RE 记录 |
| **证据** | 参考文献列表 | `source_refs` 指向具体 commit/file:line | 智能体需要可回溯的证据链 | `provenance.source_refs` + `reference_implementation` |
| **生命周期** | 发布后静态 | 版本化 + 状态变迁（draft→reviewed→published→deprecated） | 智能体需要知道知识件的新鲜度 | `version` + `status` + RE 变迁记录 |
| **下游** | 人类阅读/引用 | 自动执行（RecipeCard 步骤执行、AnchorCard 自动验证） | 智能体是执行者而非读者 | `steps[].verification` + `acceptance_criteria` |
| **前提条件** | 隐含在上下文中 | 显式 `preconditions` 分 machine_checkable / natural_language | 智能体需要可编程验证适用性 | `preconditions` 字段 |
| **错误处理** | 脚注/附录 | PitfallCard 独立形态，错误签名可自动匹配 | 智能体遇到异常时需自动排错 | `error_signature.pattern` + `root_causes` |

# LBM Ontology v1 — 双轴挂载规范
**创建日期**: 2026-11-10  
**任务锚点**: FEAT-TK-ONTOLOGY (m8816)  
**状态**: 试点落地（LBM 方法轴全量重组）
## 1. 设计原则
### 1.1 双轴挂载
每个知识节点同时挂载两个轴：
- **技术轴（Method Axis）**: LBM 能力树（碰撞算子/多相模型/边界处理/GPU与可微/湍流/热学/耦合…）
- **领域轴（Domain Axis）**: 船舶总体性能学科标签（阻力/推进/耐波/操纵/稳性/结构/振动噪声/绿色航行/冰区航行）
### 1.2 六形态重铸
不新造知识，重组既有证据为六种卡片形态：
1. **MethodCard**: 方法描述卡（≥12 张）
2. **DecisionCard**: 决策选型卡（≥6 张）
3. **AnchorCard**: 校准锚点卡（≥10 张，带期望值+容差+跑法）
4. **PitfallCard**: 陷阱警示卡（≥6 张，含 QR 判伪链）
5. **RecipeCard**: 配方卡（≥6 张）
6. **GapCard**: 缺口卡（G1-G21 全量重铸）
### 1.3 关系边
≥80 条关系边，类型包括：
- `fixes`: 修复某缺口
- `verifies`: 验证某锚点
- `alternative_of`: 某方法的替代方案
- `precondition_of`: 某方法的前置条件
- `extends`: 扩展某方法
- `validates`: 校准某参数
- `falsifies`: 证伪某假设
- `implements`: 实现某方法
- `benchmarks`: 基准测试某方法
每条边两端可回溯到具体卡片 ID。
