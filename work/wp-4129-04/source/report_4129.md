## ② 怎么做的

冲突只有 `CHANGELOG.md`，而**行级并集并不足以保证正确**。做法是「以 `main` 为骨架的按段归属重建」：

1. 取三方 stage（`:1` 基线、`:2` 分支、`:3` `main`），逐段解析为「标题 + 正文」；
2. 以 `main` 文件为骨架（含 52 个提交的全部新条目）；
3. 把 `main` 上被更早一次机械合并错位的 4 条 `## 2026-11-03 Cook 膜应力审计` 条目移回其
   自身标题下（位置以分支侧为准），并从 plane-strain B-bar 段删除；
4. 把分支独有的「均布压力板精度复核」条目注入 `## Unreleased` 段首，使重复的两个
   `## Unreleased` 标题合一；
5. 不动 `main` 其余正文与顺序——本 PR 相对 `main` 的 `CHANGELOG.md` 差异仅 51 行。

审计工具化（入仓）：`scripts/audit_changelog_merge.py` 三类检查——结构不变量（唯一
`## Unreleased`、无空段、条目归属）、**对两个父提交的多重集行保全**（重复条目不能被同款
条目掩盖）、以及**重放未解冲的文本合并并要求它被判负**。`tests/test_changelog_integrity.py`
用 2 个负控钉住两类失效模式。

## ⑤ 注意点

1. **机械 overlay 的新型失效：不丢行但把条目挂错段。** `main` 自身就带着这个损坏（Cook 段
   标题下空、4 条条目在 plane-strain 段末尾），说明它不是本分支引入的；「diff 里没有删除行」
   完全不能当作解冲正确的证据。
2. **重复 `## Unreleased` 是 overlay 指纹。** 分支侧此前一次合并留下两个 `## Unreleased`
   （一个在文件最顶部、`# Changelog` 标题之前），结构不变量检查可直接抓到。
3. **`import tensorfem` 可能指向别的 worktree。** 本机多 worktree 并行，默认解析到
   `/root/tp-agent/work/m3182/src`；验证必须 `PYTHONPATH=<本 worktree>/src` 并打印
   `tensorfem.__file__` 自证，否则测的是别人的代码。
4. **满载下 `--timeout` 会造成假失败。** load15 ≈ 1000–1300 时同一测试耗时被放大 50–100 倍，
   `--timeout=90` 把「数值正确但被饿死」的测试判成 FAILED；超时与数值失败必须分开记录。
5. **后台长任务需 `setsid`。** 仅 `nohup ... &` 会被工具在 120 s 收整组；需
   `setsid nohup ... < /dev/null > log 2>&1 &`。
6. **未修 `main` 的全局版式**（如实）：`main` 里仍有若干段正文排在 `# Changelog` 标题之前，
   且 `## Curved-bar pure bending verified against the exact Airy solution` 标题重复两次
   （第一段是截断副本）。两者都是更早机械合并遗留、非本 PR 引入；修复会造成无关的大面积
   diff，故只记录不修。
